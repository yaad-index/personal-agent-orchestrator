# ADR 0045: A channel's membership and ownership are separate grants, and an admitted inbound is preprocessed by type

**Status:** Proposed (2026-11-25)

## Context

The channel model is already rich: a channel is a communication endpoint with a per-source adapter (ADR-0009, ADR-0019); every inbound carries an authenticated per-sender id resolved to a subject (ADR-0019); a channel is a resource used for stdin and stdout (ADR-0038 point 8); who may run a command is decided per command from the sender's subject, with steering commands and answering an approval question reserved for a subject routed as the operator and `/pao help` and agent addressing open to others (ADR-0026 point 3); a group has a member policy whose only value today is "operators" (ADR-0028 point 2), and a conversation's readers are its members under the narrowest-reader rule (ADR-0028 point 5); and the operator flag is an explicit grant whose fate the access-matrix work will decide (ADR-0022 point 6).

Two things the redesign sharpens are not yet fixed: that being in a channel and being able to steer it are different grants, and how a non-text inbound reaches an agent that reads normalized messages.

## Decision

1. **Comms and access are separate.** A channel is a communication endpoint (ADR-0009, ADR-0019), and pao is multi-source. That a channel is a place messages flow is one thing; what a subject may do there is access, decided by the matrix (ADR-0005, ADR-0012), and the two are kept apart.

2. **Membership is a reader-and-participant policy.** Membership is a value of the group member policy of ADR-0028 point 2 (whose only value today is "operators"): a channel's members are the subjects its policy admits, and they are its readers under ADR-0028 point 5's narrowest-reader rule, which decides whose output and which questions may be shown there. pao cannot control who a platform shows a group to (ADR-0038's deferred item), so membership decides who counts as a reader and whose inbound is acted on, not platform visibility. Whether a member's own text reaches the agent is the stdin side of ADR-0038 point 8's channel use, which membership grants where the policy admits the member to act.

3. **Ownership is a per-channel grant for steering commands, and nothing more.** The steering commands of ADR-0026 point 3, which change a binding, a view, a default, or an agent's state, are for a channel's **owner(s)**, granted per channel under the matrix. This **narrows ADR-0026 point 3** (those commands are operator-only there) and **answers ADR-0022 point 6** (the operator flag becomes, for the chat-command axis, a per-channel ownership grant). It does **not** include **answering an approval question**, which stays the operator's alone (ADR-0038 point 7, ADR-0004 points 2 and 6, ADR-0026 point 3), and it is **not** a blanket grant: the operator owns a channel by a grant like any owner, never automatically (ADR-0012 point 2). A non-owner keeps exactly what ADR-0026 point 3 already gives it, `/pao help` and addressing the agents it may reach; any other command from a non-owner is refused as unknown, not forbidden, so the refusal reveals nothing (ADR-0026 point 3, ADR-0012 point 4).

4. **A command is handled by pao, not delivered to an agent; agent-addressed text is.** A `/pao` command, whether steering or help, is pao's to handle and is never passed to an agent (ADR-0026 point 1). Only text addressed to an agent, explicitly or by the routing precedence of ADR-0038 point 4, reaches it, as the normalized message of ADR-0010.

5. **An admitted non-text inbound is preprocessed by type before the agent.** Once a sender is attributed and admitted (ADR-0019 points 3 and 5, ADR-0028 point 2), a non-text inbound, a file, a voice clip, an image, is run through a per-type **preprocessor** pao applies first: a voice clip becomes its transcript text, an image a stored reference the agent can open, each type its own preprocessor. The agent receives the normalized result (ADR-0010) and never the raw upload in its message, and an admitted inbound of a type that has no preprocessor is refused. A **rejected** inbound, from an unbound or unadmitted sender, is recorded raw and bounded (ADR-0019 point 7) and is **never preprocessed**, so an outsider cannot make pao transcribe audio or store a file.

6. **An agent has at most one input.** An agent's input is at most one channel or conversation, a group or a named topic (ADR-0038 point 3), its home; this holds for the per-user orchestrator (ADR-0040) and any other agent alike. It names the input an agent reads and does not change ADR-0038's stdout fan-out or routing precedence.

The internals left open: the member-policy values beyond "operators" and how ownership is granted and to whom, with the access matrix (ADR-0005, ADR-0012); the preprocessor set and how a type maps to one, where a preprocessor's output lives and under what access; and whether a preprocessor may be a driver of an ADR-0039 plane or stays pao-internal.

## Consequences

Being in a channel and being able to steer it are separate grants, so a channel can be shared for reading without its command surface, while the gate answer stays the operator's and a command still never reaches an agent. Preprocessing an admitted inbound by type means an agent sees normalized text or a reference and never a raw upload, a new input type is a new preprocessor, an unknown type fails closed, and an outsider's content is recorded raw rather than processed. This **builds on ADR-0009 and ADR-0019** (the endpoint and sender identity), **ADR-0038** (the channel resource, the streams, the routing, and the operator-only gate answer), **ADR-0028** (the member policy and narrowest-reader rule), **ADR-0026** (commands decided per subject), **ADR-0010** (the normalized message), **ADR-0004** (the gate), and **ADR-0005 and ADR-0012** (the grants). It **narrows ADR-0026 point 3 and ADR-0022 point 6** for the steering-command axis, turning operator-only steering into per-channel ownership, and supersedes nothing else; ADR-0022 point 6 itself anticipates being narrowed by the access-matrix work this is part of.

The cost is membership and ownership as two grants to administer per channel, where a mis-grant of ownership widens the steering surface, which the gate still checks and which never includes the operator-only approval answer; and a preprocessor per input type to build and keep, failing closed on an unknown type and never running on a rejected inbound.
