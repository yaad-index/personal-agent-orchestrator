# pao ADRs — index

Architecture Decision Records for **pao** (personal-agent-orchestrator). Convention: ADR-0000. Broad decisions first, detail added in successive ADRs. Immutable once Accepted; a later ADR supersedes an earlier one.

A superseded ADR is never edited or deleted: it keeps a **Superseded-by** header pointing to its replacement and stays in place, out of circulation. Supersession is all-or-nothing, never partial; the successor states which parts it keeps and which it changes.

- **0014** — Budget + outbound notifications (one notifier; gate exempt; per-account budget)
- **0015** — Profile inheritance + the account field (extends 0011)
- **0016** — pao as an MCP server (pao operations as MCP tools; matrix- and gate-bound)
- **0023** — Agent I/O: channel bindings + the default agent (stdin/stdout/stderr per agent; stdout multiplexed, each channel a level against the profile map; default agent per channel, unprefixed, last in the routing precedence; `/pao` addressing by name or tag; channels as access-matrix resources shared by subjects; a single-conversation platform maps group topics to channels; extends 0003/0008/0009/0012/0013/0019)
- **0024** — pao as a proxy for upstream MCP servers (pao is an MCP client to upstream servers and re-exposes their tools on its own MCP endpoint; an agent connects to one MCP, pao's; each proxied tool is a matrix resource, shown and callable only per the caller's access, with no existence leak; every proxied call passes the matrix and gate before pao forwards it; extends 0004/0005/0012/0016)
- **0025** — An agent's context comes from its profile (superseded by 0033; by default a backend loads only its profile's working directory, pao's MCP configuration and pao's hook, nothing from the node user's environment; the backend adapter owns the isolation, a profile setting its options is refused; a profile inherits the user's context by named category; a backend that cannot isolate a category says so; contract test case; extends 0011/0015)
- **0026** — Operator commands from chat (`/pao` is pao's and never reaches an agent; a chat command is an existing operator operation under the same checks; steering and gate answers for an operator-routed subject within its access, administration stays at the operator surface; a command's answer goes only to its sender; help built from the command table and filtered by who asks; buttons are a typed command's shortcut, re-checked on press; addressing only as `/pao agent`, `/pao tag` or `/pao <name>`, no platform mention syntax; extends 0005/0009/0010/0022/0023)
- **0027** — Action buttons on a gate question (a message may carry platform-neutral actions, each a label and the typed command it stands for; interactive control is a capability interface the core consumes, with all platform code inside its adapter; the bot adapter first, any later platform its own adapter; a press is its command from the presser, re-checked, answered to the presser alone; a settled question's buttons are closed on every channel; extends 0004/0009/0010/0019/0026)
- **0028** — Group conversations, operator-only first (superseded by 0029; a group is served only when the operator admits it by the platform's conversation id, at the operator surface; each admitted group carries a member policy, first value "operators"; identity stays per sender, registration never from a group; routing as in a private conversation, last address per sender and conversation; anything shown in a conversation must be allowed for every reader, which keeps gate questions to operators; by default output goes to the group and gate questions to the group and the operators privately, per-stream multi-destination routing a follow-up ADR; the platform's group limit is the operator's prerequisite, not a decision; multi-human groups are a later policy value; extends 0012/0019/0022/0023/0026/0027)
- **0029** — Output routing (supersedes 0028, keeping its points 1-5 and replacing point 6: a destination is a conversation named with its kind (group:<name>, private:<subject>); a reply goes back to the conversation it was addressed from; configuration adds standing bindings, each a destination at its own verbosity, the highest level mirroring the whole stream including input; stderr and gate questions routed separately, by default to the operators privately; an optional operator prefix of at most 10 characters per binding; every destination still passes the narrowest-reader rule; stdin single, keeping inputs apart is the operator's job; extends 0008/0012/0023/0026)
- **0030** — The governor, a natural-language front-end for operator commands (superseded by 0031; an always-on, cheap-model agent translates a natural-language operator request into one exact ADR-0026 command and shows it back for the operator to commit; a translator with bounded read-only grants and no authority of its own, so a misparse is a visible wrong suggestion, never a wrong action; the strict `/pao` syntax stays authoritative and directly callable; extends 0026/0027/0023/0009/0004)
- **0031** — The governor, shared per node and started on demand (superseded by 0032; supersedes 0030, keeping its points 2 and 3 and point 1's role and bounded grants: invoked as `/gpao <text>` (the default prefix, configurable), pao's and never an ordinary agent's, operators only, everything it says to the requester alone; one governor per node, each read checked against its own grants and the requester's view; a fresh context per requester; started on the first request, never stopped on a timer, only by an explicit act as any agent, not a temporary agent; proposes the steering set minus gate answers and help, with a temporary agent's spawn from a recipe and its kill added to that set; a command that changes nothing may run without a commit where configured; the model's endpoint a reserved option; extends 0006/0026/0029)
- **0032** — The governor's questions and notices go to its requester (superseded by 0034; supersedes 0031, keeping its points 1-3 and 5-8: a gate question about the governor's tool call and pao's notices about it go to the subject it is serving, privately, on the request's channel, never to every operator as ADR-0029 point 4's default would; it still takes no stderr binding; with no request in hand, a question is not asked and its action refused, a notice only logged; extends 0029)
- **0033** — A provisioned working directory's settings are not loaded, and trust is answered (supersedes 0025, keeping its points 2-5: a temporary agent loads its working directory's instructions but none of the settings there, so nothing its source holds makes the backend run a command; pao answers a backend's first-run trust question, in the backend's own terminal, for a configured agent and for a temporary agent whose directory's settings are shut out; an adapter that cannot shut them out leaves the question to a person; extends 0006)
- **0034** — The governor replies where it was asked (supersedes 0032, keeping its points 1-3 and 5-8 and its stderr rule: the governor's output, its proposals, clarifying questions and refusals, goes back to the conversation the request came from, under the narrowest-reader rule, held back and never redirected when a reader may not reach it; its gate questions and pao's notices about it still go to the requester alone; a later member policy admitting narrower readers decides whether its output may go to such a group; extends 0029)
